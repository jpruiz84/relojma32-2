# Source mapping and reconstruction limits

This document distinguishes source-derived behavior and geometry from assumptions. The app is a functional reconstruction of the final `relojma.asm` (firmware version `06/12`, last assembled September 2014), using the later production PCB export and the available exterior photographs. It does not execute the PIC HEX file, simulate electrical voltages or assert unseen mechanical details as measured facts.

## Firmware behavior

The menu logo uses all 48 bytes from `LCD_DIBLOGORET` as six 5 × 8 CGRAM
characters. `ITECLADO1` writes codes 0–5 at zero-based columns 10–15 of the
first row. Both the 3D LCD texture and the control-panel display render these
same pixels directly; the logo does not depend on a font or substitute text.

## Relevant source quirks and safeguards

1. **LCD colons do not blink in this revision.** `ARELOJ` toggles the AMPM bit, but both literal branches load `':'`. The simulation therefore keeps colons steady, despite the comment and older README description.
2. **Recomputation excludes the current hour/minute.** A bell already selected before its minute will fire, but setting time or leaving a menu at that exact minute selects a later occurrence.
3. **The comparison sum is binary arithmetic on BCD differences.** `ADDWF HORADIF,W` skips any candidate whose hour and minute differences sum to zero modulo 256, not solely an equal timestamp. For example, an alarm at 11:31 is initially skipped from 10:32. This behavior is tested.
4. **Future midnight can be skipped.** The source resets the scan time to 00:00 when traversing days, and its equality exclusion skips that day's 00:00 candidate. This behavior is retained and documented rather than silently presented as a conventional modern scheduler.
5. **Corrupt memory is bounded.** Invalid active BCD timestamps and invalid day schedule IDs are retained in the imported raw EEPROM but not executed. The selector has a bounded search instead of reproducing indefinite loops or watchdog resets.
6. **Defined time-input range is guarded.** The assembly accepts hour digits up to `19` and permits `00` in a 12-hour editor. These are undefined/unintended inputs; the web editor accepts 01–12 (or 00–23 in the explicit lab editor) and valid minutes/seconds.
7. **Backlight counters saturate at zero.** The model expresses the intended 10-second timeout, rather than exposing the MCU counter's later unsigned underflow while the backlight is already off. Sub-second key-scan delays, the minimum ~100 ms manual delay, register banks, WDT reset timing and interrupt instruction latency are not emulated.
8. **Decimal password input.** Non-numeric keys during entry are ignored; the firmware's hexadecimal-key arithmetic in password entry is not treated as a supported feature. Raw EEPROM import/export still preserves every byte.
9. **RTC display scope.** The app models time and weekday because those are the fields exposed by the product UI. DS1307 calendar date/month/year registers, oscillator analog drift, battery discharge and undefined CH startup contents are not an electrical simulation.
10. **EEPROM programming is a lab capability.** Archive import and export operate directly on memory, including password bytes, like MPLAB programming. They are not additional physical keypad features. The initial demonstration schedule is explicitly distinct from archived memory and unknown factory defaults.
11. **Closed browser behavior.** Browser persistence advances the backed-up RTC by real elapsed time on reopen (bounded to one year for corrupt-clock resilience). No software running solely in an ordinary web tab can reproduce an independently powered physical controller's audible output after the tab is closed. The simulator does not replay past bells.

## Electrical source and conflicts

`Circuitos/Version 2/placa real.SDF` is the readable ISIS export: 28 parts and 47 nets. The `.EDF` supplies exact footprint anchors and rotations. `.ses` supplies 98 routed paths. `placa real.PDF` is **PCB copper/silkscreen artwork**, not a circuit schematic sheet. The browser offers that artwork and the actual schematic netlist separately.

- PIC U2: 40-pin PIC16F877A, 4 MHz oscillator, EEPROM inside the PIC.
- RTC U1: DS1307, X1 = 32.768 kHz, BAT1 = 3 V CR2032, SQW to RB0, SDA = RA4 and SCL = RA3.
- U3: 7805, 12 V input, 5 V logic output.
- Q1/R1: RC1-controlled LCD backlight through J1.
- Q2/R4/J3: external 12 V relay driver.
- **J5 is a series link from RC0 to R4 and Q2**, so the model treats the top switch as a physical inhibit for both programmed and manual output. Firmware never reads a switch input. `RING!!` and RC0 can therefore be active with the physical contact open. This follows the schematic even though the panel/manual calls it an automatic-bell switch.
- The manufacturing BOM specifies a **12 V / 40 A relay**, while the external usable contact is protected/rated at **15 A** by the fuse and manual. The UI does not confuse the relay's standalone rating with the protected load rating.
- SDF C3/C4 say **2000 µF**; the BOM says **1000 µF / 16 V**. Inspection retains the SDF value, with this conflict documented. No analog filtering behavior is inferred.
- SDF X2's `FREQ` property says **32.768 kHz**, while the PIC `CLOCK=4MHz`, XT configuration and manufacturing BOM identify the PIC crystal as **4 MHz**. The simulator uses 4 MHz for the PIC description and flags the mismatch in its inspector.
- Older optotriac/MOC experiments in `Circuitos/` are prototypes, not simultaneously installed parts. They are not added to the later relay-based assembly.

## Verification

The deterministic test suite checks the EEPROM boundary addresses and all eight captured memory files, preserved partial imports, BCD quirks, weekday rollover, duplicate times, all four pulse patterns, accelerated playback, manual-release behavior, J5 and fuse gating, every keypad menu, password confirmation/timeouts, power interruption and RTC reset.

The Playwright suite exercises the running React/Three.js application, including actual 3D front-panel picking, opening/exploding the cover, inspecting a source net, physical-keyboard input, schedule persistence through reload, imported/exported captures, timed bell actuation, password recovery, a 390 px mobile viewport and dialog focus containment. Manual screenshot inspection covers assembled, open and mobile views.
